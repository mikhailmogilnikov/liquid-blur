<Section id="start" title="Get started">

Layout watches an element and its items, its children unless you say otherwise. When you put an item in, take one out, reorder them, change a class or let a size change, every item that moved is shown where it was and goes to where it is now on a spring. A size that changed changes for real, so text is never squeezed, and what comes after it in the page moves along.

<Only js>

<Steps>
<Step>

**Install.**

<Install pkg="@fluidkit/core" />

</Step>
<Step>

**Call `createLayout` on the element whose items move.**

```ts
import { createLayout } from "@fluidkit/core";

createLayout({ root: document.querySelector<HTMLElement>(".list")! });
```

</Step>
<Step>

**Change the page as you always would.** Layout sees it before it's painted and moves everything from where it was.

```ts
list.prepend(row); // put in: the rows after it slide down, it fades in
row.remove(); // taken out: it fades where it was, the rest close up
list.append(...[...list.children].reverse()); // reordered: each slides to its place
section.classList.add("open"); // a size that changed: it grows, what's under it moves down
```

</Step>
</Steps>

</Only>

### Reminders

Put one in at the top and the rest slide down while it fades in. Tick one off and it fades where it was while the rows under it close up. Shuffle, and each row slides to its new place. Do it again before they've stopped: they turn around from where they are, keeping their speed.

<Example>
<LayoutExample kind="list" />

<Fragment slot="html">

```html
<ul class="list">
  <li class="row"><button class="tick" aria-label="Done"></button>Book the train to Lyon</li>
  <li class="row"><button class="tick" aria-label="Done"></button>Call the dentist</li>
  …
</ul>
```

</Fragment>
<Fragment slot="js">

```ts
import { createLayout } from "@fluidkit/core";

const list = document.querySelector<HTMLElement>(".list")!;
createLayout({ root: list });

// Ticked off: the row goes
list.addEventListener("click", (e) => (e.target as Element).closest(".tick")?.closest("li")?.remove());

function add(text: string) {
  const row = document.createElement("li");
  row.className = "row";
  row.textContent = text;
  list.prepend(row);
}

function shuffle() {
  const rows = [...list.children].sort(() => Math.random() - 0.5);
  list.append(...rows);
}
```

</Fragment>
<Fragment slot="react">

```tsx

  const [todos, setTodos] = useState(initial);
  const add = (text: string) => setTodos((t) => [{ id: crypto.randomUUID(), text }, ...t]);
  const done = (id: string) => setTodos((t) => t.filter((todo) => todo.id !== id));
  const shuffle = () => setTodos((t) => [...t].sort(() => Math.random() - 0.5));
  return (
    <Layout.Root render={<ul className="list" />}>
      {todos.map((todo) => (
        <li key={todo.id} className="row">
          <button className="tick" aria-label="Done" onClick={() => done(todo.id)} />
          {todo.text}
        </li>
      ))}
    </Layout.Root>
  );
}
```

</Fragment>

```vue
      </li>
    </ul>
  </Layout.Root>
</template>
```

### Photos

Filter the grid and the photos that don't match fade where they were, while the rest slide to their new cells. Back to All, the others fade in where they belong. Nothing here knows it's a grid: Layout follows whatever the browser lays out.

<Example>
<LayoutExample kind="grid" />

<Fragment slot="js">

```ts
import { createLayout } from "@fluidkit/core";

const grid = document.querySelector<HTMLElement>(".grid")!;
const photos = [...grid.children];
createLayout({ root: grid });

function show(match: (photo: Element) => boolean) {
  const keep = photos.filter(match);
  for (const photo of photos) if (!keep.includes(photo)) photo.remove();
  grid.append(...keep);
}
```

</Fragment>

```tsx
  );
}
```

### Settings

A section opens by its real height on a spring: its text is revealed, never squeezed, and the sections under it and the card after them move down with it. Open another while the first is still opening and both carry on together.

<Example>
<LayoutExample kind="settings" />

<Fragment slot="js">

```ts
import { createLayout } from "@fluidkit/core";

const sections = document.querySelector<HTMLElement>(".sections")!;
createLayout({ root: sections });

for (const section of sections.children) {
  section.querySelector("button")!.addEventListener("click", () => section.classList.toggle("open"));
}
```

</Fragment>
<Fragment slot="react">

```tsx
import { useState } from "react";
import { Layout } from "@fluidkit/react";

export function Settings({ sections }: { sections: { title: string; text: string }[] }) {
  const [open, setOpen] = useState<string | null>(null);
  return (
    <Layout.Root className="sections">
      {sections.map(({ title, text }) => (
        <section key={title}>
          <button aria-expanded={open === title} onClick={() => setOpen(open === title ? null : title)}>
            {title}
          </button>
          {open === title && <p>{text}</p>}
        </section>
      ))}
    </Layout.Root>
  );
}
```

</Fragment>
<Fragment slot="vue">

```vue
<script setup lang="ts">
import { ref } from "vue";
import { Layout } from "@fluidkit/vue";

defineProps<{ sections: { title: string; text: string }[] }>();
const open = ref<string | null>(null);
</script>

<template>
  <Layout.Root class="sections">
    <section v-for="{ title, text } in sections" :key="title">
      <button :aria-expanded="open === title" @click="open = open === title ? null : title">{{ title }}</button>
      <p v-if="open === title">{{ text }}</p>
    </section>
  </Layout.Root>
</template>
```

</Fragment>
<Fragment slot="svelte">

```svelte

</script>

    <section>
      <button aria-expanded={open === title} onclick={() => (open = open === title ? null : title)}>{title}</button>
      {#if open === title}<p>{text}</p>{/if}
    </section>
  {/each}
</Layout.Root>
```

<Section id="moving" title="How it moves">

**From where it was drawn.** A change is seen before the browser paints it, and each item that moved is shown exactly where it was, then moves to where it is now. Another change on the way sets off from where everything is drawn at that moment, keeping its speed: nothing jumps, however fast the changes come.

**Positions, then sizes.** A moved item goes on `translate`. An item whose size changed, and the root itself, change size for real: `width` and `height` on the spring, what's past the size clipped along that axis while it grows. Text isn't squeezed, corners and shadows aren't stretched, and what comes after them in the page moves with them instead of jumping. With `size: false`, sizes change at once and only positions move.

**In and out.** A new item comes in where it is, faded and a little smaller unless told (`enter`, any of [Motion's transitions](/motion#transitions)). One taken out of the page goes out where it was (`exit`): the element itself, put back in its place for the while, out of the flow, inert and hidden from assistive technology, then removed. Put back in the page meanwhile, it stays and moves from where it was. An item hidden with `display: none` just goes.

**What it touches.** While an item moves, its inline `translate` is the layout's, added to its own: a [drag](/drag)'s offset, or its stylesheet's. `transform` is never touched, so a [press](/blur#press) stretching glass or a [morph](/morph) flying it goes on as it does, and an item being dragged (`data-dragging`) isn't moved. While it comes in or goes out, its `scale` (times its own) and `opacity` are the layout's; while its size changes, its `width`, `height` and what would hold them back, including its flex along the container's main axis. Everything is put back as it was once it's at rest.

**What it sees.** Items put in, taken out or moved, the `class` and `hidden` of the root and its items, and their sizes. A change none of these show, say an item's inline `style` or a class on an ancestor that moves items without resizing them, is followed on `update()`. Scrolling isn't a change: positions are read inside the root, its scroll included. With reduced motion everything changes at once, and so it does while the root is hidden (in a tab not shown, say) and as it's shown again.

</Section>

<Section id="morph" title="Layout or Morph?">

Both move things on springs, for different changes. [Morph](/morph) turns one element into another: a button into a panel, a row into a page. Layout moves an element to where the page has put it now: the same row, further down; the same section, taller. A list with rows that open into panels can use both, Layout on the list and Morph on each row.

</Section>

<Section id="performance" title="Performance">

Moves are translations and cost almost nothing. Sizes change for real, so the browser lays out what depends on them each frame, only while they move: in a component, a list or a card, under a couple of milliseconds a frame on a phone. A section high up in a long page lays out everything under it each frame; measured over five hundred rows on a mid-range phone's CPU, under 8ms a frame. If a page is much heavier, use `size: false` there, or give what's under it less to lay out.

</Section>

<Section id="options" title="Options" only="js">

`createLayout(options: LayoutOptions): Layout`

| Option | Description |
| --- | --- |
| `root: HTMLElement` | The element whose items move |
| `items?: string` | Its items, as a selector inside it. Default: its children |
| `spring?: SpringParams` | The spring everything moves on. Default: `springs.snappy()`, `{ duration: 0.26, bounce: 0.15 }`. See [Motion](/motion#springs) |
| `size?: boolean` | Sizes change on the spring too. Default: `true`. `false` changes them at once and moves only positions |
| `enter?: TransitionParams \| false` | How a new item comes in: a [transition](/motion#transitions). Default: `transitions.scale()`. `false`: it's there at once |
| `exit?: TransitionParams \| false` | How an item taken out goes. Default: the same. `false`: it's gone at once |
| `onStart?: () => void` | Called when something sets off moving, from rest |
| `onRest?: () => void` | Called when everything has come to rest |

</Section>

<Section id="api" title="API" only="js">

| Member | Description |
| --- | --- |
| `moving` | `true` while something is on its way |
| `update()` | Reads the layout again and follows it, for a change no watcher sees |
| `set(settings)` | Updates any option except `root` and `items`, without recreating it |
| `destroy()` | Stops watching. Everything still moving is put where it is at once, and every style it wrote put back |

</Section>

<Section id="composition" title="Composition" only="react vue svelte">

<Only react>

**Render as your own element.** `Layout.Root` accepts `render`, as in Base UI: pass an element and our props are merged into it, or a function that receives the props and state (`{ moving }`).

```tsx
<Layout.Root render={<ul className="list" />}>{rows}</Layout.Root>
```

**Glass.** Render it as [`Glass`](/blur#components), and its items as glass too: a [glass group](/blur#groups) melts with them as they move.

```tsx
<Layout.Root render={<Glass.Group className="toolbar" />}>{tools}</Layout.Root>
```

</Only>
<Only vue>

**Render as your own element.** `Layout.Root` accepts `as-child`, as in Reka UI: it renders the first element in its slot, with our attributes and ref merged in. The slot also receives its state (`{ moving }`).

```vue
<Layout.Root as-child>
  <ul class="list">…</ul>
</Layout.Root>
```

**Glass.** Render it as [`Glass`](/blur#components), and its items as glass too: a [glass group](/blur#groups) melts with them as they move.

```vue
<Layout.Root as-child>
  <Glass.Group class="toolbar">…</Glass.Group>
</Layout.Root>
```

</Only>
<Only svelte>

**Render as your own element.** `Layout.Root` accepts a `child` snippet, as in bits-ui: spread the `props` it gives onto your element. They carry the attachment that connects it. The snippet also receives its state (`{ moving }`).

```svelte
<Layout.Root>
  {#snippet child({ props })}<ul {...props} class="list">…</ul>{/snippet}
</Layout.Root>
```

**Glass.** Put the props on a [glass group](/blur#groups), and its items glass too: the group melts with them as they move.

```svelte
<Layout.Root>
  {#snippet child({ props })}
    <Glass.Group {...props} class="toolbar">…</Glass.Group>
  {/snippet}
</Layout.Root>
```

</Only>

<Section id="hook" title="The hook" only="react vue svelte">

<Only react>

Use `useLayout(options)` when the component doesn't fit your markup. It takes the same options as `Layout.Root` and returns a ref.


<Only vue>

Use `useLayout(options)` when the component doesn't fit your markup. Options can be an object, a ref or a getter; a getter is read again when what it uses changes. It returns a function ref for `:ref`.

```vue
<script setup lang="ts">
import { useLayout } from "@fluidkit/vue";

const layout = useLayout({ size: false });
</script>

<template>
  <ul :ref="layout.root">…</ul>
</template>
```

| Member | Description |
| --- | --- |
| `root` | Function ref for the element whose items move |
| `moving` | Ref: `true` while something is on its way |
| `update()` | Reads the layout again, for a change no watcher sees |
| `layout` | Shallow ref to the underlying engine, once mounted |

</Only>
<Only svelte>

Use `useLayout(() => options)` when the component doesn't fit your markup. Call it in a component's script; the options getter is read again when what it uses changes. It returns an attachment for `{@attach}`, and state you read like any other.

```svelte
<script lang="ts">
  import { useLayout } from "@fluidkit/svelte";

  const layout = useLayout(() => ({ size: false }));
</script>

<ul {@attach layout.root}>…</ul>
```

| Member | Description |
| --- | --- |
| `root` | Attachment for the element whose items move |
| `moving` | `true` while something is on its way |
| `update()` | Reads the layout again, for a change no watcher sees |
| `layout` | The underlying engine, once mounted |

</Only>
