<Section id="start" title="Get started">

Drag moves an element with a pointer, along one axis or both. It follows the pointer exactly and stretches like rubber past its bounds. On release, it springs to a snap point, starting at the pointer's speed, so a flick goes as far as you'd expect. Grab it while it's moving and it stops under your finger.

### A sheet

Three positions: open, half way, and collapsed to the title. A slow drag settles on the nearest one; a hard flick can go from the bottom all the way to the top. Past the ends it stretches like rubber.

The list inside scrolls, and one finger gesture can move both, like in iOS: push up from half way and the sheet opens first, then the list scrolls. Pull down and the list scrolls back to the top before the sheet moves. See [A list inside](#scroll).

### Swipe actions

Rows like in Mail: swipe right to mark as read, left to flag or delete. Swipe all the way and the outer action fills the row and runs on release. `axis: "x"` leaves vertical scrolling to the browser, so you can still scroll the list. There are five snap points, from fully right to fully left. A lower `deceleration` makes a full swipe need a real pull, not just a flick.

```ts
import { createDrag, type Drag } from "@fluidkit/core";

const LEAD = 92;
const TRAIL = 168;
// Snap points: fully right, left action, closed, right actions, fully left
const ALL_RIGHT = 0;
const CLOSED = 2;
const ALL_LEFT = 4;
const drags = new Map<HTMLElement, Drag>();
// remove(row) and toggleUnread(row) are your own functions

for (const row of document.querySelectorAll<HTMLElement>(".row")) {
  const face = row.querySelector<HTMLElement>(".row__face")!;
  const drag = createDrag({
    element: face,
    axis: "x",
    snaps: () => [row.clientWidth, LEAD, 0, -TRAIL, -row.clientWidth],
    initial: CLOSED,
    deceleration: 0.99,
    onStart: () => {
      for (const [other, d] of drags) if (other !== row && d.current !== CLOSED) d.snap(CLOSED);
    },
    onMove: ({ x }) => {
      // Width for the actions; past half way to the edge, the outer action fills the row
      row.style.setProperty("--x", String(x));
      const w = row.clientWidth;
      row.toggleAttribute("data-full", x < -(TRAIL + w) / 2 || x > (LEAD + w) / 2);
    },
    // A full swipe runs the action on release
    onEnd: (snap) => {
      if (snap === ALL_LEFT) remove(row);
      if (snap === ALL_RIGHT) {
        toggleUnread(row);
        // Then slide back closed
        queueMicrotask(() => drag.snap(CLOSED));
      }
    },
  });
  drags.set(row, drag);
  // Drags don't fire clicks, so this is a tap
  face.addEventListener("click", () => drag.current !== CLOSED && drag.snap(CLOSED));
  row.querySelector(".delete")!.addEventListener("click", () => {
    drag.snap(ALL_LEFT);
    remove(row);
  });
  // Unread and Flag: run the action, then drag.snap(CLOSED)
}
```

```tsx
import { useRef, useState } from "react";
import { Drag } from "@fluidkit/react";

const LEAD = 92;
const TRAIL = 168;
// Snap points: fully right, left action, closed, right actions, fully left
const ALL_RIGHT = 0;
const CLOSED = 2;
const ALL_LEFT = 4;

export function Inbox({ mails }: { mails: Mail[] }) {
  // Which row is open, and how far. Only one at a time
  const [open, setOpen] = useState<{ id: string; snap: number } | null>(null);
  return (
    <ul className="inbox lb">
      {mails.map((mail) => (
        <Row
          key={mail.id}
          mail={mail}
          snap={open?.id === mail.id ? open.snap : CLOSED}
          onSnapChange={(snap) => setOpen(snap === CLOSED ? null : { id: mail.id, snap })}
          // Starting to swipe another row closes this one
          onStart={() => setOpen((o) => (o?.id === mail.id ? o : null))}
        />
      ))}
    </ul>
  );
}

type RowProps = { mail: Mail; snap: number; onSnapChange: (snap: number) => void; onStart: () => void };

function Row({ mail, snap, onSnapChange, onStart }: RowProps) {
  const row = useRef<HTMLLIElement>(null);
  // remove(mail) and toggleUnread(mail) are your own functions
  return (
    <li ref={row} className="row">
      <div className="row__lead" aria-hidden="true">
        <button
          type="button"
          className="unread"
          tabIndex={-1}
          onClick={() => {
            toggleUnread(mail);
            onSnapChange(CLOSED);
          }}
        >
          Unread
        </button>
      </div>
      <div className="row__trail" aria-hidden="true">
        <button type="button" className="flag" tabIndex={-1} onClick={() => onSnapChange(CLOSED)}>
          Flag
        </button>
        <button
          type="button"
          className="delete"
          tabIndex={-1}
          onClick={() => {
            onSnapChange(ALL_LEFT);
            remove(mail);
          }}
        >
          Delete
        </button>
      </div>
      <Drag.Root
        className="row__face"
        axis="x"
        snaps={({ width }) => [width, LEAD, 0, -TRAIL, -width]}
        snap={snap}
        deceleration={0.99}
        onStart={onStart}
        onMove={({ x }) => {
          // Width for the actions; past half way to the edge, the outer action fills the row
          const el = row.current!;
          el.style.setProperty("--x", String(x));
          el.toggleAttribute("data-full", x < -(TRAIL + el.clientWidth) / 2 || x > (LEAD + el.clientWidth) / 2);
        }}
        // A full swipe runs the action on release; after marking, slide back closed
        onSnapChange={(next) => {
          if (next === ALL_LEFT) remove(mail);
          if (next === ALL_RIGHT) toggleUnread(mail);
          onSnapChange(next === ALL_RIGHT ? CLOSED : next);
        }}
        // Drags don't fire clicks, so this is a tap
        onClick={() => onSnapChange(CLOSED)}
      >
        …
      </Drag.Root>
    </li>
  );
}
```

### A switch

The thumb is the dragged element and the whole switch is its `handle`. Drag it and it goes to the side the flick points to; tap it to toggle. `rubberband: 0` keeps it inside the track. A short `follow` spring makes it trail the pointer slightly, so quick back-and-forth movement looks smooth. The thumb is glass: solid white at rest, and [a lens](/blur#classes) while held, using Liquid Blur's `--lb-lens` and `--lb-transparency` on `data-dragging`.

<Section id="snapping" title="Snapping">

On release, Drag doesn't pick the snap point closest to where you let go. It estimates where the element would stop if it kept sliding and slowed down like a scroll, and picks the snap point closest to that. A slow drag stays near; a flick can skip past points in between. iOS picks sheet positions and picture-in-picture corners the same way.

`deceleration` controls how fast that imagined slide slows down, per millisecond. The default `0.998` matches scrolling; `0.99` stops sooner, so flicks reach less far. Without snap points, the element stops where the slide would end, within its bounds.

The release spring starts at the pointer's speed. The default spring has no bounce, but a hard flick still overshoots once and comes back, like iOS sheets. Overshooting past the bounds stretches like rubber; with `rubberband: 0` it stops at the edge.

</Section>

<Section id="options" title="Options" only="js">

`createDrag(options: DragOptions): Drag`

| Option | Description |
| --- | --- |
| `element: HTMLElement` | The element to move. Drag owns its inline `translate` |
| `handle?: HTMLElement` | The element to grab, like a sheet's grabber or a whole switch. Default: `element` |
| `axis?: "x" \| "y" \| "both"` | Direction of movement. Default: `both` |
| `scroll?: HTMLElement` | A scrollable area inside, like a sheet's list. One gesture can [scroll it and move the element](#scroll). `x` or `y` axis only |
| `snaps?: DragSnaps \| () => DragSnaps` | Where it can come to rest: offsets along the axis, or `{ x, y }` points for `both`. A function is called again when the element, its parent or the window resizes |
| `bounds?: DragBounds \| () => DragBounds` | `{ x?: [min, max], y?: [min, max] }`. Past these it stretches like rubber. Default: the outermost snap points, or no limit without snaps |
| `initial?: number` | Index of the starting snap point. Default: `0` |
| `rubberband?: number` | Resistance past the bounds. Default: `0.55`, as in iOS. `0` stops at the edge |
| `deceleration?: number` | How fast a flick slows down, per millisecond. Default: `0.998` |
| `spring?: SpringParams` | The release spring. Default: `{ duration: 0.4, bounce: 0 }`. See [core](/core#spring) |
| `follow?: SpringParams` | If set, the element trails the pointer on this spring instead of sticking to it exactly |
| `onStart?: () => void` | Called when a drag starts, or when the element is grabbed mid-motion |
| `onMove?: (position, velocity) => void` | Called whenever it moves, with its offset and speed in px/s. Use it to sync other things, like a backdrop's opacity |
| `onEnd?: (snap) => void` | Called on release with the target snap point (`null` without snaps) |
| `onRest?: () => void` | Called when it stops moving |

</Section>

<Section id="api" title="API" only="js">

| Member | Description |
| --- | --- |
| `position` | Current offset, `{ x, y }` |
| `velocity` | Current speed in px/s, `{ x, y }` |
| `dragging` | `true` while a pointer is dragging it |
| `moving` | `true` while dragged or animating |
| `current` | Index of the current or target snap point. `null` after `to()`, or without snaps |
| `disabled` | Set to `true` to stop dragging. An active drag is released |
| `snap(index, move?)` | Animates to a snap point. `{ instant: true }` jumps there; `{ velocity }` sets the starting speed |
| `to(position, move?)` | Animates to an offset within the bounds: a number along the axis, or `{ x, y }` |
| `update()` | Recomputes snap points and bounds, and keeps the same snap point |
| `set(settings)` | Updates any option except `element`, `handle`, `axis`, `scroll` and `initial`, without recreating the drag |
| `destroy()` | Stops it, removes listeners, and restores the element's `translate` and the handle's `touch-action` |

| `snap?: number` | Current snap point, for controlled use |
| `defaultSnap?: number` | Initial snap point, for uncontrolled use. Default: `0` |
| `onSnapChange?: (snap) => void` | Called when it's released toward a different snap point |
| `disabled?: boolean` | Disables dragging. An active drag is released |
| `rubberband?: number` | Resistance past the bounds. Default: `0.55`. `0` stops at the edge |
| `deceleration?: number` | How fast a flick slows down, per millisecond. Default: `0.998` |
| `spring?: SpringParams` | The release spring. Default: `{ duration: 0.4, bounce: 0 }`. See [core](/core#spring) |
| `follow?: SpringParams` | If set, the element trails the pointer on this spring |
| `onStart?: () => void` | Called when a drag starts, or when the element is grabbed mid-motion |
| `onMove?: (position, velocity) => void` | Called every frame it moves. Update the DOM directly here; setting state would re-render every frame |
| `onEnd?: (snap) => void` | Called on release with the target snap point (`null` without snaps) |
| `onRest?: () => void` | Called when it stops moving |

**Controlled.** Pass `snap` and `onSnapChange` to keep the position in your state. If you don't accept the new value, it goes back to `snap`.

```tsx
const [snap, setSnap] = useState(1);
<Drag.Root snap={snap} onSnapChange={setSnap}>…</Drag.Root>
<button onClick={() => setSnap(0)}>Open</button>
```

Changing props never recreates the drag, and callbacks always see the latest values. Changing `axis`, or adding a handle or scroll area, recreates it at the same position.

</Only>

<Section id="composition" title="Composition" only="react vue svelte">

<Only react>

**Render as your own element.** Every part accepts `render`, as in Base UI: pass an element and our props are merged into it, or a function that receives the props and state (`{ snap, dragging }`).

```tsx
<Drag.Root axis="y" snaps={snaps} render={<section aria-label="Nearby" />}>
  <Drag.Scroll render={<ul className="list" />}>{rows}</Drag.Scroll>
</Drag.Root>
```

**Glass.** Make it glass with `className="lb"`, or render it as [`Glass`](/blur#components). Drag only writes `translate`, so press effects keep working.

```tsx
import { Glass } from "@fluidkit/react";

<Drag.Root axis="y" snaps={snaps} render={<Glass render={<section className="sheet" />} />}>…</Drag.Root>
```

**Handle outside the element.** With parts, the handle sits inside the moving element. For a switch or slider it's the other way round (the thumb is inside the handle), so use [the hook](#hook), as the examples above do.

**Styling.** `data-snap` on the root shows the current snap point, `data-dragging` is there while it's dragged.

</Only>
<Only vue>

**Render as your own element.** Every part accepts `as-child`, as in Reka UI: instead of its own element, the part renders the first element in its slot, with our attributes, classes, styles, listeners and refs merged in. The slot also receives the part's state (`{ snap, dragging }`).

```vue
<Drag.Root axis="y" :snaps="snaps" as-child>
  <section aria-label="Nearby">
    <Drag.Scroll as-child><ul class="list">…</ul></Drag.Scroll>
  </section>
</Drag.Root>
```

**Glass.** Make it glass with `class="lb"`, or render it as [`Glass`](/blur#components). Drag only writes `translate`, so press effects keep working.

```vue
<Drag.Root axis="y" :snaps="snaps" as-child>
  <Glass as-child><section class="sheet">…</section></Glass>
</Drag.Root>
```

**Handle outside the element.** With parts, the handle sits inside the moving element. For a switch or slider it's the other way round (the thumb is inside the handle), so use [the composable](#hook), as the examples above do.

**Styling.** `data-snap` on the root shows the current snap point, `data-dragging` is there while it's dragged.

</Only>
<Only svelte>

**Render as your own element.** Every part accepts a `child` snippet, as in bits-ui: instead of its own element, the part renders yours. Spread the `props` it gives onto your element: they carry our attributes, handlers and the attachment that connects it. The snippet also receives the part's state (`{ snap, dragging }`).

```svelte
<Drag.Root axis="y" {snaps}>
  {#snippet child({ props })}
    <section {...props} aria-label="Nearby">
      <Drag.Scroll>
        {#snippet child({ props })}<ul {...props} class="list">…</ul>{/snippet}
      </Drag.Scroll>
    </section>
  {/snippet}
```

<Section id="hook" title="The hook" only="react vue svelte">

<Only react>

Use `useDrag(options)` when the parts don't fit your markup. It takes the same options as `Drag.Root` and returns refs.

```tsx
import { useDrag } from "@fluidkit/react";

const drag = useDrag({ axis: "x", snaps: ({ width, element }) => [0, width - element.offsetWidth] });

<div ref={drag.handle} className="track">
  <span ref={drag.element} className="thumb" />
</div>
```

| Member | Description |
| --- | --- |
| `element`, `handle`, `scroll` | Refs for the moving element, the handle and the scroll area |
| `snap` | Current snap point |
| `dragging` | `true` while dragged |
| `snapTo(index, move?)` | Animates to a snap point. `{ instant: true }` jumps there; `{ velocity }` sets the starting speed |
| `to(position, move?)` | Animates to an offset within the bounds |
| `drag` | The underlying engine, once mounted: `position`, `velocity`, `update()` |

</Only>
<Only vue>

Use `useDrag(options)` when the parts don't fit your markup. Options can be an object, a ref or a getter; a getter is read again when what it uses changes. It returns function refs for `:ref`.

```vue
<script setup lang="ts">
import { useDrag } from "@fluidkit/vue";

const drag = useDrag({ axis: "x", snaps: ({ width, element }) => [0, width - element.offsetWidth] });
</script>

<template>
  <div :ref="drag.handle" class="track">
    <span :ref="drag.element" class="thumb" />
  </div>
</template>
```

| Member | Description |
| --- | --- |
| `element`, `handle`, `scroll` | Function refs for the moving element, the handle and the scroll area |
| `snap` | Computed: the current snap point |
| `dragging` | Ref: `true` while dragged |
| `snapTo(index, move?)` | Animates to a snap point. `{ instant: true }` jumps there; `{ velocity }` sets the starting speed |
| `to(position, move?)` | Animates to an offset within the bounds |
| `drag` | Shallow ref to the underlying engine, once mounted: `position`, `velocity`, `update()` |

To put two refs on one element (yours and the drag's), use one function that calls both, as the switch above does.

</Only>
<Only svelte>

Use `useDrag(() => options)` when the parts don't fit your markup. Call it in a component's script; the options getter is read again when what it uses changes. It returns attachments for `{@attach}`, and state you read like any other.

```svelte
<script lang="ts">
  import { useDrag } from "@fluidkit/svelte";

  const drag = useDrag(() => ({ axis: "x", snaps: ({ width, element }) => [0, width - element.offsetWidth] }));
</script>

<div {@attach drag.handle} class="track">
  <span {@attach drag.element} class="thumb"></span>
</div>
```

| Member | Description |
| --- | --- |
| `element`, `handle`, `scroll` | Attachments for the moving element, the handle and the scroll area |
| `snap` | The current snap point |
| `dragging` | `true` while dragged |
| `snapTo(index, move?)` | Animates to a snap point. `{ instant: true }` jumps there; `{ velocity }` sets the starting speed |
| `to(position, move?)` | Animates to an offset within the bounds |
| `drag` | The underlying engine, once mounted: `position`, `velocity`, `update()` |

An element can take the drag's attachment and your own `bind:this` side by side, as the switch above does.

</Only>

<Section id="gesture" title="The gesture">

<Rows>
<Row>
<Cell title="Starting">

A drag starts after the pointer moves 4px (8px on touch), so taps stay taps. With one axis, moving across it first is left to the page: you can scroll a list past rows that swipe sideways. With nested handles, like swipeable rows inside a sheet, the innermost one wins.

</Cell>
<Cell title="Touch">

Drag sets the handle's `touch-action` so the browser keeps the other axis: `pan-y` for `x`, `pan-x` for `y`, `none` for `both`. Pinch-zoom still works. Once a drag starts, the page doesn't scroll under the finger.

</Cell>
</Row>
<Row>
<Cell title="Clicks">

The click at the end of a drag is cancelled, so dragging a button doesn't press it, while tapping does. Drags don't start on text fields, and links and images in the handle can't be dragged out by the browser.

</Cell>
<Cell title="Measuring">

Offsets are in the element's own pixels, so it tracks the pointer in a scaled container too. While dragged, it has `data-dragging`, and text on the page can't be selected. With reduced motion, it still follows the pointer but snaps instantly on release.

</Cell>
</Row>
</Rows>

Roles, labels and keyboard support are up to you: a sheet's `dialog` role, a switch's `role="switch"` and click handler, arrow keys on a slider. Drag only handles movement.

</Section>

<Section id="scroll" title="A list inside">

A sheet with a scrollable list can share one gesture between the two, like in iOS. Pass the list as `scroll` (in React, Vue and Svelte, use `Drag.Scroll`). For touch:

<Rows>
<Row>
<Cell title="What moves">

The sheet moves when you pull it toward later snap points (down, for a bottom sheet) while the list is at the top, or push it the other way while it isn't fully open. Otherwise the list scrolls. Outside the list, on the grabber or title, the sheet always moves.

</Cell>
<Cell title="Within one gesture">

Push the sheet fully open and the rest of the gesture scrolls the list. Pull down and the list scrolls back to the top, then the sheet follows. In Chrome, a scroll in progress can't be interrupted, so the sheet moves on the next pull.

</Cell>
</Row>
</Rows>

With a mouse, dragging moves the sheet and the wheel scrolls the list. Add `overscroll-behavior: contain` to the list so scrolling doesn't continue to the page. `scroll` works only with the `x` or `y` axis.

</Section>

<Section id="glass" title="With Liquid Blur">

The element can be glass, like the sheet and the video above. Drag only writes `translate`, so Liquid Blur's press effects keep their `scale` and `transform`.

</Section>

<Section id="support" title="Browser support">

Any browser with ES2022, Pointer Events, `ResizeObserver` and the `translate` property.

</Section>

<Section id="limitations" title="Limitations">

- Rotated ancestors aren't supported; scaled ones are.
- If snap points depend on something other than the element, its parent or the window size, call `update()` when it changes.

</Section>
