<Section id="start" title="Get started">

Install the package, import the stylesheet once, and add the `lb` class to any element.


<Step>

**Set up press effects** if you use the press classes (`lb-highlight`, `lb-swell`, `lb-stretch`, `lb-interactive`). It adds a single listener to the document, so elements added later work too, in any framework. On the server it does nothing.

```ts

installPress();
```

### A lens while held

A lens is the same glass without blur, so what's underneath shows through sharply. `lb-lens` makes glass a lens permanently. To switch to a lens only while something is held, animate `--lb-lens` from 0 to 1 instead; it's a registered property, so it transitions, as does `--lb-transparency`. For example, a switch thumb that's solid white at rest and becomes a clear lens while pressed or dragged (with [Drag](/drag#examples), which adds `data-dragging`), like in iOS:

```css
.switch__thumb {
  --lb-transparency: 0;
  --lb-fill: #fff;
  transition: --lb-lens 0.3s, --lb-transparency 0.3s, scale 0.35s;
}
.switch:active .switch__thumb,
.switch__thumb[data-dragging] {
  --lb-lens: 1;
  --lb-transparency: 1;
  scale: 1.45 1.5;
}
```

```html
<button class="switch" role="switch" aria-checked="true">
  <span class="switch__thumb lb"></span>
</button>
```

The lens doesn't magnify; that would need refraction. With the system's reduced transparency or increased contrast settings, it stays solid.

<Section id="layers" title="Layers">

The glass is made of these layers, from back to front. It only uses features that render the same in every browser engine, and no pseudo-elements, so `::before` and `::after` are free for you.

1. **Backdrop**: blur and saturation.
2. **Fill**: one color (or the tint) at a calculated opacity.
3. **Volume**: the surface darkens toward the edges and catches a little light under the top and bottom rims.
4. **Rims**: thin highlights along the top and bottom. On a capsule they fade toward the ends.
5. **Edge**: a thin dark line just outside.
6. **Drop shadow.**

</Section>

<Section id="customize" title="Customize">

All variables are inherited: set one on any ancestor and all glass inside uses it.

<VarTable />

```css
.toolbar {
  --lb-transparency: 0.8;
  --lb-depth: 0.3;
}

.danger {
  --lb-tint: #ff3b30;
}
```

Variables starting with `--_` are internal and may change without notice.

</Section>

<Section id="colors" title="Colors">

Colors are resolved on each glass element, so they follow the theme that applies there. Transparency and depth still control how strong the color looks.

```css
/* Your own neutral color per theme */
:root {
  --lb-fill-light: #f5f5f7;
  --lb-fill-dark: #1c1c1e;
}

/* Warm glass: amber fill, shading and rims */
.warm {
  --lb-fill-light: #ffe08a;
  --lb-shade-color: #5a2a00;
  --lb-shine-color: #fff4c0;
}

/* Same fill in both themes */
.brand {
  --lb-fill: #0a3;
}

/* A light tint needs dark text */
.warning {
  --lb-tint: #ffcc00;
  --lb-tint-text: #111;
}
```

Text color is picked automatically to contrast with the fill. To override it, set `color` on the element, or `--lb-text`.

</Section>

<Section id="theming" title="Theming">

The theme is a single inherited variable, `--lb-dark`: `0` for light, `1` for dark. By default it follows the system setting. `data-theme="light"` or `"dark"` on any element switches everything inside it.

```html
<html data-theme="dark">
  <section data-theme="light">
    <button class="lb">Always light</button>
  </section>
</html>
```

To connect another theme switcher, set `--lb-dark` on its dark-theme selector:

```css
/* Tailwind, shadcn, next-themes with attribute="class" */
.dark { --lb-dark: 1; }

/* daisyUI and other named themes */
[data-theme="dracula"] { --lb-dark: 1; }
```

</Section>

<Section id="tailwind" title="Tailwind & layers">

All styles are in `@layer liquid-blur`, so your own unlayered CSS overrides them without `!important`. Tailwind v4 declares its layers on import, and the first declared layer has the lowest priority, so glass imported after Tailwind would override utilities like `rounded-xl`. Declare the layer order once, before both imports:

```css
@layer liquid-blur, theme, base, components, utilities;
@import "tailwindcss";
@import "@fluidkit/core/style.css";
```

</Section>

<Rows>
<Row>
<Cell title="Pressed state">

While pressed, the element has `data-lb-pressed`, which you can style. On touch it appears after a short delay, so starting a scroll doesn't trigger it. A quick tap still flashes briefly.

</Cell>
<Cell title="Highlight">

A soft glow under the finger. It grows with the element, up to a limit on large panels. `--lb-highlight-size` scales it.

</Cell>
</Row>
<Row>
<Cell title="Springs">

Highlight and swell run on springs that can reverse mid-way. While animating, the script sets `scale`, the highlight strength and the press position (`--lb-press-x`, `--lb-press-y`) inline, and removes them when done. Swell multiplies your own `scale`.

</Cell>
<Cell title="Size">

Larger glass swells and stretches less, and moves slower. `--lb-swell` and `--lb-stretch` set the strength, and `--lb-stretch-axis` (`x`, `y` or `both`) the direction. A switch thumb, for example, should only stretch along its track.

</Cell>
</Row>
<Row>
<Cell title="Stretch">

Only writes `transform`, once per frame, without reading layout. Your own transform is kept, and your inline `transform` and `will-change` are restored afterwards. Stretch sets `touch-action: none` and disables text selection on the element.

</Cell>
<Cell title="Release outside">

Releasing more than 32px outside the element cancels the click.

</Cell>
</Row>
</Rows>

Don't add a CSS `transition` on `scale` (for swell) or `transform` (for stretch): the script updates them every frame, and a transition would lag. Use press classes on individual controls, not containers: highlight lights up the whole element, and stretch blocks scrolling and text selection inside it.

Disabled controls (`:disabled` or `aria-disabled="true"`) get no press effects. Their disabled look is up to you.

</Section>

Groups need `installGlassGroups()`; the components set them up for you. Without it, or while the children are far apart, they look like ordinary glass.

<Only js>

**Server rendering.** The entry is safe to import on the server, where `installGlassGroups()` does nothing. In React, Vue or Svelte, call it after hydration (in an effect), because the group adds its own elements to the root. Write both `lb lb-group` in your markup, so a re-render doesn't drop `lb`.

```tsx
import { useEffect } from "react";
import { installGlassGroups } from "@fluidkit/core";

export function Toolbar() {
  // After hydration, since the group adds its own elements to the root
  useEffect(() => installGlassGroups(), []);
  return (
    // Include "lb" in the markup so a re-render keeps it
    <div className="lb lb-group">
      <div className="lb">…</div>
      <button className="lb lb-interactive">…</button>
    </div>
  );
}
```

</Only>

</Only>

<Section id="components" title="Components" only="react vue svelte">

<Only react>

**`Glass`** renders a `div`, or your own element with `render` (as in Base UI). Your classes and styles are kept.

| Prop | Description |
| --- | --- |
| `clear?: boolean` | Clearer glass for photos and video (`lb-clear`) |
| `tint?: boolean \| string` | Fill with a color. Pass a color, or `true` to use the inherited `--lb-tint` (`lb-tinted`) |
| `lens?: boolean` | Glass without blur (`lb-lens`) |
| `transparency?: number` | `0` opaque, `0.5` default, `1` clear (`--lb-transparency`) |
| `depth?: number` | `0` flat, `0.5` default, `1` pronounced (`--lb-depth`) |
| `interactive?: boolean` | Highlight, swell and stretch (`lb-interactive`) |
| `highlight?`, `swell?: boolean` | Individual press effects (`lb-highlight`, `lb-swell`) |
| `stretch?: boolean \| "x" \| "y"` | Stretch, optionally along one axis (`lb-stretch`, `--lb-stretch-axis`) |

Press props set up press effects automatically, including inside iframes.

**`Glass.Group`** renders a `div` with `lb lb-group`, or your own element, and turns it into a [glass group](#groups). `merge` sets how close children get before merging, in px (default `18`). `transparency` and `depth` work like on `Glass` and apply to all children.

```tsx
<Glass.Group className="toolbar" merge={24}>
  <Glass interactive render={<button aria-label="Back" />}><BackIcon /></Glass>
  <Glass interactive render={<button aria-label="Share" />}><ShareIcon /></Glass>
</Glass.Group>
```

**Hooks and helpers.**

- `glass(variants)` returns `{ className, style }` for the same props, for elements that aren't `Glass`, like a router `Link`.
- `usePress()` sets up press effects, if you write the press classes by hand.
- `useGlassGroup()` returns a ref for a group root (with `lb lb-group`) and the group itself, so you can call `update()`.

```tsx
import { glass, useGlassGroup, usePress } from "@fluidkit/react";

const { className, style } = glass({ interactive: true, tint: "#0a84ff" });
<Link className={className} style={style} href="/follow">Follow</Link>;

const { root, group } = useGlassGroup();
<div ref={root} className="lb lb-group">…</div>;
```

```svelte
    {#snippet child({ props })}<button {...props} aria-label="Back"><BackIcon /></button>{/snippet}
  </Glass>
  <Glass interactive>
    {#snippet child({ props })}<button {...props} aria-label="Share"><ShareIcon /></button>{/snippet}
  </Glass>
</Glass.Group>
```

**Functions and helpers.**

- `glass(variants)` returns `{ class, style }` for the same props, to spread onto elements that aren't `Glass`: `<a {...glass({ interactive: true })} href="/follow">`.
- `usePress()` sets up press effects, if you write the press classes by hand.
- `useGlassGroup()` returns an attachment for a group root (with `lb lb-group`) and the group itself, so you can call `update()`.

```svelte
<script lang="ts">
  import { glass, useGlassGroup } from "@fluidkit/svelte";

  const toolbar = useGlassGroup();
</script>

<a {...glass({ interactive: true, tint: "#0a84ff" })} href="/follow">Follow</a>
<div {@attach toolbar.root} class="lb lb-group">…</div>
```

<Section id="api" title="API">

The functions behind press effects and groups. See [Entries](#entries) for where each one comes from.

**`installPress(root?: Document): () => void`**<br />
Sets up press effects on `root` (default: `document`) and returns a function that removes them. Calling it again returns the same function. While active, `<html>` has `data-lb-interaction`. Works in open shadow roots; for an iframe, pass its `contentDocument`. Does nothing without a DOM.

```ts
const uninstall = installPress();

// An iframe has its own document
installPress(frame.contentDocument);

// Later, to remove it
uninstall();
```

**`installGlassGroups(root?: Document): () => void`**<br />
Turns every `.lb-group` in the document into a group, including ones added later, and cleans up groups whose root is removed. Returns a cleanup function; calling it again returns the same one. Does nothing without a DOM.

**`createGlassGroup(root: HTMLElement): GlassGroup`**<br />
Creates a group for a single element you manage yourself. Adds `lb` and `lb-group` to `root` if missing. Calling it again for the same root returns the existing group.

```ts
import { createGlassGroup } from "@fluidkit/core";

const group = createGlassGroup(toolbar);

// After moving a child in a way the group can't detect
group.update();

// Later
group.destroy();
```

</Section>

<Section id="support" title="Browser support">

Any browser with `backdrop-filter`, `color-mix()` and CSS `pow()`. Without `@property` (Firefox before 128) the glass still renders, but some settings leak into nested glass and the press highlight doesn't fade. Groups also need `clip-path: path()`, `mask` with inline SVG, and Canvas 2D. The JavaScript is ESM targeting ES2022. [Scroll edges](/edge) need scroll-driven animations (Chrome 115, Safari 26); elsewhere there's no fade.

</Section>

<Section id="limitations" title="Limitations">

- **Backdrop roots.** Glass only blurs what's inside its backdrop root. An ancestor with `filter`, `opacity` below 1, `mask`, `clip-path`, `mix-blend-mode` or its own `backdrop-filter` hides everything behind that ancestor from the glass.
- **Transforms on groups.** Scaling a group or its ancestors works; rotating doesn't. Movement the group can't detect needs `update()`. The merged shape uses circular corners, even for squircle children.
- **Clipping around a group.** In Chromium, an ancestor with `overflow: hidden` (or `clip`, or paint containment) and a `corner-shape` other than `round` shows a blurred rectangle around merged glass. Put the shape on the ancestor's background instead and don't clip. Clipping with plain `border-radius` is fine.
- **No refraction.** See the [FAQ](#faq). A lens doesn't magnify.
- **Lenses in groups.** While merged, a group draws its children's glass as one surface, lenses included. Don't put lens glass directly in a group.

</Section>

<Section id="faq" title="FAQ">

<Faq>
<Question q="Why no refraction?">

Refraction on the web needs SVG filters, which only one browser engine applies to a backdrop, and they're expensive on every frame while scrolling. Liquid Blur only uses what renders the same in every browser.

</Question>
<Question q="Does it need JavaScript?">

No. The material is plain CSS. The optional scripts add press effects and glass groups.

</Question>
<Question q="How do I use it with React, Vue or Svelte?">

In React, Vue and Svelte, use `Glass` (see [Components](#components) with your framework chosen). Elsewhere, use the classes and set up press effects once in your root component; `installPress()` returns its own cleanup.

<Only js>

```tsx
import { useEffect } from "react";
import { installPress } from "@fluidkit/core";

export function App() {
  useEffect(() => installPress(), []);
  return <button className="lb lb-highlight">Glass</button>;
}
```

</Only>

</Question>
<Question q="How fast is it?">

A backdrop filter costs GPU time proportional to the area of glass on screen: a toolbar is cheap, a full-page panel isn't. While animating, the scripts only write transforms and two CSS variables per frame and never read layout.

</Question>
<Question q="Is this Apple's Liquid Glass?">

No. It's inspired by it, but has no refraction and only uses what browsers support today.

</Question>
</Faq>
