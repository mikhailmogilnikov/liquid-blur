<Section id="start" title="Get started">

A morph flows between states: real elements, each laid out where and as it is at rest. One is shown, the others are hidden. Asked for another, a single shape flows from the box of the one shown to the box of the other, and at rest that element is itself again. Here the states are a button and its panel.

<Steps>
<Step>

**Install.**

<Install pkg="@liquid-web/morph" />

</Step>
<Step>

**Lay out both states** where they are at rest. Hide the panel with `visibility: hidden` so it can still be measured, and put it above the button (`z-index: 2`). Each state has its own surface: here both are [Liquid Blur](/blur) glass, but any styling works.

```html
<div class="morph-scene">
  <button id="more" class="lb" type="button" aria-controls="panel" aria-expanded="false">More</button>
  <div id="panel" class="lb">
    <p>Panel content</p>
    <button id="close-panel" type="button">Close</button>
  </div>
</div>

<style>
  .morph-scene { position: relative; min-height: 240px; }
  #more { width: 88px; height: 44px; border-radius: 22px; }
  #panel {
    position: absolute;
    left: 0;
    top: 0;
    width: min(280px, 100%);
    height: 220px;
    box-sizing: border-box;
    padding: 20px;
    border-radius: 28px;
    visibility: hidden;
    z-index: 2;
  }
</style>
```

</Step>
<Step>

**Create the morph** after the elements are in the DOM, and send it to a state from your own handlers. What a menu needs on top (its `aria-expanded`, Escape, focus) is yours, in `onStart` and `onRest`.

```ts
import "@liquid-web/blur/style.css"; // the glass, if the states are glass
import { createMorph } from "@liquid-web/morph";

const button = document.getElementById("more")!;
const panel = document.getElementById("panel")!;
const close = document.getElementById("close-panel")!;

const morph = createMorph({
  states: [button, panel],
  onStart(to) {
    button.setAttribute("aria-expanded", String(to === panel));
    // The panel is itself on its way in: focus can go into it at once
    if (to === panel) close.focus({ preventScroll: true });
  },
  onRest(at) {
    if (at === button && panel.contains(document.activeElement)) button.focus({ preventScroll: true });
  },
});

const toggle = () => morph.to(morph.current === panel ? button : panel);
const back = () => morph.to(button);
const onKey = (e: KeyboardEvent) => e.key === "Escape" && back();
button.addEventListener("click", toggle);
close.addEventListener("click", back);
document.addEventListener("keydown", onKey);

// On unmount:
// button.removeEventListener("click", toggle);
// close.removeEventListener("click", back);
// document.removeEventListener("keydown", onKey);
// morph.destroy();
```

</Step>
</Steps>

<Section id="match" title="Shared elements">

Mark an element in each of two states with the same `data-lw-match`, and it flies from where it is in one to where it is in the other, crossing over from one to the other on the way. Here the pill's icon flies into the menu's title, and its label into the option picked. Pick another and the pill comes back with it.

<Fragment slot="js">

```ts
import "@liquid-web/blur/style.css";
import { createMorph } from "@liquid-web/morph";

const sort = document.getElementById("sort")!;
const panel = document.getElementById("sort-panel")!;

const morph = createMorph({
  states: [sort, panel],
  onStart: (to) => sort.setAttribute("aria-expanded", String(to === panel)),
});

sort.addEventListener("click", () => morph.to(morph.current === panel ? sort : panel));

// A pick relabels the pill and moves the match to its label: that's the one that flies back
panel.addEventListener("click", (e) => {
  const pick = (e.target as Element).closest<HTMLElement>("[role=menuitemradio]");
  if (!pick) return;
  for (const option of panel.querySelectorAll<HTMLElement>("[role=menuitemradio]")) {
    option.setAttribute("aria-checked", String(option === pick));
    const label = option.querySelector("span")!;
    if (option === pick) label.dataset.lwMatch = "sort";
    else delete label.dataset.lwMatch;
  }
  sort.querySelector("span")!.textContent = pick.textContent!.trim();
  morph.to(sort);
});
document.addEventListener("keydown", (e) => {
  if (e.key === "Escape") morph.to(sort);
});
```

```ts
import "@liquid-web/blur/style.css";
import { createMorph } from "@liquid-web/morph";

const dot = document.getElementById("dot")!;
const bar = document.getElementById("bar")!;
const card = document.getElementById("card")!;
const states = [dot, bar, card];

const morph = createMorph({
  states,
  onStart(to, from) {
    // Focus follows into the state on its way in
    if (from.contains(document.activeElement)) {
      const target = to === dot ? dot : to.querySelector<HTMLElement>("#expand, #collapse");
      target?.focus({ preventScroll: true });
    }
  },
});

// One step in by the states themselves, one step out by Escape
dot.addEventListener("click", () => morph.to(bar));
document.getElementById("expand")!.addEventListener("click", () => morph.to(card));
document.getElementById("collapse")!.addEventListener("click", () => morph.to(bar));
document.addEventListener("keydown", (e) => {
  const step = states.indexOf(morph.current);
  if (e.key === "Escape" && step > 0) morph.to(states[step - 1]);
});
```

<Section id="options" title="Options">

`createMorph(options: MorphOptions): Morph`

| Option | Meaning |
| --- | --- |
| `states: HTMLElement[]` | The elements it flows between, each with a parent in the DOM, laid out where it is at rest |
| `initial?: HTMLElement` | The one shown at the start; the first state by default |
| `container?: HTMLElement` | Where to put the shape instead of next to the smaller state. Use it when that state's parent has `overflow: hidden` |
| `spring?: { grow?, shrink? }` | Springs for flowing into a bigger box and into a smaller one; anything left out uses `defaultMorphSprings` |
| `onStart?: (to, from) => void` | Called when a flight sets off, including when it turns around or heads elsewhere mid-way |
| `onRest?: (at) => void` | Called when it comes to rest as a state |

Each direction has five channels: `x` and `y` move the center, `width` and `height` change the size, and `progress` drives the corners, the contents and shared elements. Pass only the channels you change; `defaultMorphSprings` is exported as a starting point. A spring is `{ duration, bounce, settle? }`: `duration` in seconds, `bounce` from `0` (no overshoot) to `1`, and `settle` the bounce after the first overshoot, `bounce` by default. Shrinking from rest, the shape holds a beat while the contents go first.

```ts
const morph = createMorph({
  states: [button, panel],
  spring: {
    grow: { y: { duration: 0.4, bounce: 0.3, settle: 0.1 } },
  },
});
```

</Section>

<Section id="api" title="API">

| Member | Meaning |
| --- | --- |
| `current` | The state asked for; changes immediately |
| `moving` | Whether a flight is under way |
| `to(state, move?)` | A `Promise<boolean>`: `true` once it rests there, `false` if it was sent elsewhere or destroyed first. `{ instant: true }` swaps at once, as with reduced motion |
| `update()` | Measures the states again and follows them mid-flight |
| `destroy()` | Stops the flight, removes the shape and gives every state its own inline styles back. Later calls do nothing |

Sent back mid-way, it turns around keeping its speed. Sent to a third state mid-way, it starts over from where the shape is. During a flight it follows scrolling and window resizes by itself; call `update()` after anything else moves a state. `destroy()` doesn't remove your own event listeners.

</Section>

<Section id="layout" title="Layout">

<Rows>
<Row>
<Cell title="The bigger state">

Flies itself, either way: the real element, moved through its inline `transform`, `opacity`, `filter` and `clip-path` alone, so its text never reflows and it stays live (pressed, typed into, playing). Don't transition those. Its own translation, such as `translate: -50% -50%` for centering, is kept. Its surface steps aside for the shape meanwhile, so it has to be above it (`z-index: 2`).

</Cell>
<Cell title="The smaller state">

Rides in the shape as a copy, taken as it is when the shape sets off or turns around, staying where it is and fading as the shape leaves it. The copy keeps its classes and attributes, so style states with them: selectors through the state's parent don't reach it.

</Cell>
</Row>
<Row>
<Cell title="Surfaces">

The shape is the bigger state's surface the whole way. Where the smaller one's is another as drawn (fill, border, shadow, backdrop, pseudo-elements), it lies over it and fades as the shape grows: a solid control dissolves into glass, a tint into none.

</Cell>
<Cell title="The corners">

Each corner animates from one state's radius to the other's and stays circular, so a sheet rounded only on top stays square below. Percentages resolve against the box; an elliptical corner uses the smaller of its two radii. Where `corner-shape` is supported, the shape animates too.

</Cell>
</Row>
<Row>
<Cell title="Hidden states">

A state not shown is hidden (`opacity: 0`, `visibility: hidden`, with `data-lw-away`) and takes no presses. One that holds focus as it goes keeps it: it's only made transparent, so a control's `aria-expanded` is still announced. Pressing the shape on its way presses the smallest state under it, so a button can be pressed again before the shape is home.

</Cell>
<Cell title="Mounting">

Can be imported on the server. Create the morph in the browser after mounting or hydration, and call `destroy()` on unmount. The shape is added next to the smaller state only while it flies, so `:last-child` and similar selectors still match at rest. With reduced motion, the states swap instantly.

</Cell>
</Row>
</Rows>

</Section>

<Section id="glass" title="With Liquid Blur">

Inside a Liquid Blur [glass group](/blur#groups), the shape is placed by the state in the group, and the behavior depends on where the other one is:

- **Beside the neighbors:** the shape stays in the group and merges with the neighboring glass as it moves.
- **Over a neighbor:** the shape leaves the group and flies as separate glass above it (`z-index: 1`). A stub stays in the state's place and shrinks away, so the connection to the neighbors fades out gradually.

In a group the shape wears the bigger state's classes, as the group needs to melt it, so surfaces don't dissolve into each other there. The two packages don't import each other; they coordinate through attributes in the DOM.

If a parent clips with `overflow: hidden`, the shape would be cut off. Pass a `container` and it's placed there instead. It then inherits theme and custom properties from the container.

</Section>

<Section id="react" title="React">

A small hook creates the morph on mount and destroys it on unmount. Keep the panel's `visibility: hidden` in CSS, not inline, so a re-render doesn't override the morph.

```tsx
import { useEffect, useRef, useState } from "react";
import { createMorph, type Morph, type MorphOptions } from "@liquid-web/morph";

/** A button and its panel; options are read once, on mount */
export function useMorph(options: Omit<MorphOptions, "states"> = {}) {
  const button = useRef<HTMLButtonElement>(null);
  const panel = useRef<HTMLDivElement>(null);
  const morph = useRef<Morph | null>(null);
  const [open, setOpen] = useState(false);
  useEffect(() => {
    const m = createMorph({
      ...options,
      states: [button.current!, panel.current!],
      onStart(to, from) {
        setOpen(to === panel.current);
        options.onStart?.(to, from);
      },
    });
    morph.current = m;
    return () => m.destroy();
  }, []);
  return {
    button,
    panel,
    open,
    toggle: () => morph.current?.to(open ? button.current! : panel.current!),
    close: () => morph.current?.to(button.current!),
  };
}

export function More() {
  const morph = useMorph();
  return (
    <div className="morph-scene">
      <button
        ref={morph.button}
        className="lb"
        type="button"
        aria-controls="panel"
        aria-expanded={morph.open}
        onClick={morph.toggle}
      >
        More
      </button>
      <div ref={morph.panel} id="panel" className="lb" role="menu">
        <button type="button" onClick={morph.close}>Close</button>
      </div>
    </div>
  );
}
```

</Section>

<Section id="support" title="Browser support">

Any browser with ES2022 and `clip-path: inset()`. Corner shapes animate where `corner-shape` is supported; elsewhere corners stay round.

</Section>

<Section id="limitations" title="Limitations">

- Rotated or scaled ancestors aren't supported, and the bigger state can't have a transform of its own other than a translation.
- The smaller state's copy is a snapshot: a video or a field in it doesn't play or update on the way.
- The bigger state's pseudo-elements stay drawn while its surface steps aside.
- Corners animate as circular arcs; the corner shape follows the top-left corner.
- While the shape merges with a glass group, its corners are round.

</Section>
